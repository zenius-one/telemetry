# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

## What this is

`telemetry` is a pnpm + Turborepo + Changesets monorepo of generic, reusable telemetry packages for services.
Nothing here may know about a specific product: product policy lives in the consuming repository, behind the interfaces these packages define.

```
packages/readthrough/        Go core module: read-through cache protection (stampede, delayed
                             stampede, penetration, avalanche) over a cachestore.CacheStore.
                             Depends on cachestore-go and x/sync only. No Prometheus.
packages/readthrough/prom/   Go module: Prometheus implementation of readthrough.Observer.
.ai/                         skills and references (the source of truth for process)
.github/                     workflows, release scripts, publish configs, templates
```

Each Go module has a `package.json` next to its `go.mod`: a version-tracking shim whose scripts
(`build`, `lint`, `check-types`, `test`) call the Go toolchain so Turborepo and Changesets treat it
like any package. It is never published to npm.

## Commands

```sh
pnpm install
pnpm turbo run build lint check-types test       # everything
cd packages/readthrough && go test -race ./...   # one module
pnpm changeset                                    # interactive; agents write the file by hand
```

Go resolves the modules locally through the root `go.work`. Anything that must behave as a
consumer sees it (a release build) uses `GOWORK=off`.

## Rules that are easy to get wrong

- **Packages stay generic.** No product-specific concepts (tenant, org, plane, region, PII policy)
  in a package's API. Consumers adapt; packages do not know them.
- **Core modules take no observability backend.** Prometheus/OTel code goes in a separate module
  (`readthrough/prom`), so a service that does not use it never pulls it.
- **Behaviour is documented in the package README** and covered by tests in the same change.
- **One issue = one PR** (`CONTRIBUTING.md`); branch `<type>/<issue-number>-short-description`.
- **A change to a module needs a changeset**, written by hand (`.changeset/<slug>.md`); a
  README-only change needs none and starts no workflow.
- **Never hand-edit** `.changeset/config.json`'s `ignore` list; it is generated by
  `node .github/scripts/sync-changeset-ignore.mjs --write`.
- **A cache error must never fail a request.** Treat store errors as misses; never put a secret or
  raw PII in a key (hash it).
- The prom module pins a _released_ core version; bump it deliberately after core releases (see
  commit-strategy). Never pin a tag that does not exist.
